## MKCloud 是做什么的

MKCloud 是一家 2023 年成立的中国云服务商，只做一件事：精品专线。它卖的是 IEPL（国际以太网专线）和 IPLC（国际私有租用电路）这两类独享线路，主攻中国大陆—香港、日本、美国三个方向，目标客户是跨境电商和需要稳定国际连接的企业业务。

它和普通跨境 VPS 的区别在底层线路上。普通 VPS 走公网，高峰期和谁挤一条路全看运气；MKCloud 的线路有明确的入口和出口——广州方向接入 UCloud 的八线 BGP，香港出口走 Nearoute 的精品线路。落到体感上，就是广州到香港的 IEPL 网内延迟能稳定在 3ms 左右。

三种技术的差别值得先弄清楚：

- **IEPL**：二层以太网技术，带宽扩容灵活，同价位下性能普遍更好。广州—香港方向网内延迟约 3ms。
- **IPLC**：传统点对点独享电路，资历老，胜在稳。上海—日本约 25–28ms，上海—美国约 124ms，带宽完全独享，高峰期没有别人跟你抢。
- **IXP 优化线路**：走的也是优化路由，但没上独享专线，价格更低。和 IEPL/IPLC 比，大致是商务舱和头等舱的差别。

1. **大陆—香港方向的日常业务**：广州—香港 IEPL 是 MKCloud 的旗舰线路，网内延迟 3ms 左右，体感接近本地连接。做跨境电商、需要频繁访问国际服务的业务，从这条线起步最省心。

3. **中国—美国方向**：上海—美国 IPLC，延迟约 124ms。物理距离摆在那里，这个数字对独享线路来说属于正常水平；IPLC 的价值在于延迟稳定、带宽独享，而不是把 124ms 变成 30ms。
4. **预算敏感、想先跑通模式**：IXP 优化线路价格更低，路由同样经过优化，日常表现好于普通公网，只是没有独享带宽的保障。

## 下单前后要注意的几件事

第一个要核对的是流量口径。IEPL-500GB 的 500GB 是**双向合计**——上传和下载都计入额度，这是估算用量时最容易踩的坑。按 150Mbps 满速不间断传输计算，七个多小时就能把 500GB 跑完。实际业务很少满速，但如果你有持续的大流量传输（备份、视频流这类），建议按双向口径把月用量算出余量再选档位。

第二个是入口城市。广州入口对应香港方向，上海入口对应日本和美国方向，三条线是独立产品线，各有各的价格体系。下单前先确认业务侧靠近哪个入口、目标在哪一端，别在下单页上选错方向。

线路到手后，建议先验证质量再决定要不要转长周期：

1. 对线路端点做 ping 或 traceroute，看延迟是否落在标称范围（广州—香港 3ms、上海—日本 25–28ms、上海—美国 124ms 附近）。
2. 这些数字都是**网内延迟**，只覆盖专线那一段。你的完整链路 = 本地到入口城市 + 网内段 + 出口到目标服务器。从家宽直接 ping 出来的数字一定会更高，这不代表线路虚标。
3. 高峰期和空闲期各测一次。独享线路的价值恰恰体现在高峰期数字纹丝不动。

## 常见问题

**MKCloud 的 IEPL 和普通跨境 VPS 有什么区别？**
底层线路不同。普通 VPS 走公网共享链路，高峰期延迟和丢包不可控；IEPL 是二层以太网专线，带宽可按需扩容，广州—香港方向网内延迟约 3ms。代价是价格明显高于普通 VPS——¥198/月的预算能买到配置高得多的普通 VPS，但拿不到独享链路的稳定性。

**500GB 双向流量够不够用？**
看业务形态。网页访问、ERP、API 调用这类流量，500GB 相当充裕；持续大文件传输或视频类业务就要另算。记住两点：上传也算流量，150Mbps 满速跑七小时左右就会用完一整档。

**标称延迟为什么和我测出来的不一样？**
口径不同。3ms、25ms、124ms 都是网内延迟，你本地到入口、出口到目标这两段走的是普通网络，延迟取决于你自己的网络环境。评估线路本身，应该分段测，或者对比高峰期和空闲期的波动幅度。

**IXP 优化线路什么时候值得选？**
预算优先、且业务能容忍共享链路波动的时候。它走优化路由，日常表现好于普通公网，价格低于同方向 IPLC，但没有独享带宽保障，适合先低成本验证业务，之后再按需升级。
